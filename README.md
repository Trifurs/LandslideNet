## Overview

LandslideNet provides a research workflow for mapping landslide susceptibility from **aligned environmental-factor rasters** and a **landslide inventory**. The associated study focuses on large-scale mapping in Pakistan.

The current codebase supports:

- Terrain-derived, contiguous physiographic macro-regions for spatially separated evaluation.
- Fold-specific feature processing and regional training/validation/test splits.
- **DWSS** and **random** negative-sampling experiments.
- LandslideNet, ablation variants, and machine-learning/deep-learning comparison models.
- Full-domain susceptibility prediction and export of reproducibility diagnostics.

The repository includes the training and prediction pipeline; compatible study data and local path configuration must be supplied separately.

## Method

### LandslideNet architecture

The proposed model is implemented in [`models/landslidenet.py`](models/landslidenet.py). Its principal components are:

- **Convolution–BatchNorm–ReLU (CBR)** input stem.
- **Spatial Perception Blocks (SPB)** with deformable convolution and residual connections.
- **Dynamic Channel Squeeze-and-Excitation (DCSE)** for channel-wise feature recalibration.
- **Feature Pyramid Network (FPN)** for multi-scale feature fusion.
- A dense two-class prediction head.

The repository also contains controlled ablation variants that disable SPB and/or DCSE. For the original architecture figure and scientific interpretation, refer to the [paper](https://doi.org/10.1016/j.rse.2026.115710).

### Terrain-based regionalization

The first stage constructs label-independent physiographic macro-regions from terrain factors. The default configuration uses DEM, slope, relief, roughness, topographic position index (TPI), and topographic wetness index (TWI).

These continuous regions define geographically separated model evaluation partitions instead of conventional random pixel splits.

### DWSS and regional evaluation

The experiment pipeline supports **DWSS** and a **random negative-sampling** control. In the current XML configuration, DWSS uses joint Gaussian kernel-density estimation, three Jenks natural-break strata, a minimum threshold of 0.55, and a 1:1 positive/negative sampling ratio.

Feature transformations and DWSS sampling are fitted using the relevant training regions rather than held-out test regions. Fold-level sampling and preprocessing audits are saved for reproducibility.

### Full-area prediction

After training, [`3_model_predict.py`](3_model_predict.py) generates raster susceptibility outputs. Deep-learning models use **multi-stride median fusion (MSMF)**; classical models use direct per-pixel inference.

## Installation

**Requirements:** Python 3.10 (as specified in the provided Conda environment), compatible PyTorch/torchvision packages, and geospatial Python dependencies. GPU acceleration is recommended for large-scale deep-learning experiments.

Clone the repository and create the supplied environment:

```bash
git clone https://github.com/Trifurs/LandslideNet.git
cd LandslideNet

conda env create -f environment.yml
conda activate landslidenet
```

To update an existing environment:

```bash
conda env update -n landslidenet -f environment.yml
```

The environment includes PyTorch, torchvision, NumPy, SciPy, pandas, scikit-learn, rasterio, GeoPandas, CatBoost, LightGBM, and related packages. Ensure your PyTorch/torchvision builds match the operating system and CUDA setup.

## Data Preparation

The workflow requires:

1. **Environmental-factor rasters:** individual aligned layers covering the study area.
2. **Landslide inventory:** a point Shapefile/GeoPackage, or a compatible aligned inventory raster supported by the training pipeline.

An illustrative layout is:

```text
data/
├── factors/
│   ├── DEM.tif
│   ├── Slope.tif
│   └── ...                        # Other aligned factor rasters
└── landslides/
    ├── landslides.shp
    ├── landslides.shx
    ├── landslides.dbf
    └── landslides.prj
```

Factor rasters must share **CRS, extent, resolution, dimensions, and grid alignment**. Vector inventory points are projected to the factor grid, and multiple landslide points falling in the same raster cell are deduplicated.

**Data and pretrained weights:** The original study rasters, inventory, and pretrained model checkpoints are **not bundled with this repository**. Consult the paper for data availability and contact the author if more information is needed.

## Configuration

The main configuration file is [`Landslide_susceptibility_mapping.xml`](Landslide_susceptibility_mapping.xml). **Update its absolute paths before running the scripts.** The committed example contains paths from the original development machine.

| XML parameter | Purpose |
| --- | --- |
| `input_factors_dir` | Directory containing aligned factor rasters |
| `landslide_inventory` | Landslide points or compatible label raster |
| `num_bands` | Number of input factors (default: 20) |
| `macro_region_output` | Output path for region raster; supports `{count}` |
| `macro_region_count` | Number of macro-regions (default: 5) |
| `experiment_sampling_methods` | Sampling arms (default: `dwss,random`) |
| `model` | Proposed, comparison, or ablation model selection |
| `device_ids` | Compute device identifiers; adjust to your hardware |
| `train_output` | Base experiment directory unless overridden |

The XML also contains settings for DWSS, validation, optimization, augmentation, and prediction. Review these before applying the pipeline to a different dataset.

## Quick Start

Run the three stages **from the repository root**, after preparing data and correcting the XML paths.

### Step 1 — Build physiographic macro-regions

```bash
python 1_data_processing.py Landslide_susceptibility_mapping.xml
```

This builds or checks the terrain-derived regions specified by the configuration.

### Step 2 — Train LandslideNet

```bash
python 2_model_train.py \
  Landslide_susceptibility_mapping.xml \
  --models landslidenet \
  --output-dir ./outputs/experiment
```

The supplied XML requests both DWSS and random sampling arms by default.

To resume an interrupted run **using the same XML and model selection**:

```bash
python 2_model_train.py \
  Landslide_susceptibility_mapping.xml \
  --models landslidenet \
  --output-dir ./outputs/experiment \
  --resume
```

A fresh training run requires a new or empty output directory. **The training command does not support `--overwrite`.**

### Step 3 — Generate susceptibility maps

```bash
python 3_model_predict.py \
  ./outputs/experiment \
  --models landslidenet \
  --sampling-methods dwss random
```

The positional argument is the **completed experiment directory** from Step 2. Prediction also supports `--output-dir`, `--resume`, and `--overwrite` (the last two apply to prediction outputs, not training). See `python 3_model_predict.py --help` for more options.

## Supported Models

The registered model names and groups are defined in [`utils/model_registry.py`](utils/model_registry.py).

| Experiment group | Model identifiers |
| --- | --- |
| Proposed — `proposed` | `landslidenet` |
| Machine learning — `machine_learning` | `logistic_regression`, `catboost`, `extra_trees`, `lightgbm`, `random_forest` |
| Deep learning — `deep_learning` | `dbpfnet`, `da_lsf`, `lgc_net` |
| Ablation — `ablation` | `baseline`, `only_dcse`, `only_spb` |
| All — `all` | All registered models |

Example: train the proposed model together with classical comparisons.

```bash
python 2_model_train.py \
  Landslide_susceptibility_mapping.xml \
  --models proposed machine_learning \
  --output-dir ./outputs/comparison
```

> **Comparison-model note:** DBPFNet, DA-LSF, and LGC-Net are **task-adapted implementations** for the static raster-factor setting, not official reproductions released by the respective original authors.

## Outputs and Evaluation

Training and prediction stages export model checkpoints, split manifests, configuration snapshots, training histories, evaluation reports, and raster susceptibility maps.

| Output | Description |
| --- | --- |
| `all_models_5fold_metrics.csv` | Fold metrics and five-fold mean/standard-deviation summaries |
| `all_models_training_history.csv` | Available per-epoch or per-round histories |
| `validation_protocol.json` | Resolved regional validation protocol |
| `configuration_snapshot.xml` | Experiment-specific configuration copy |
| `fold_leakage_audit.json` | Preprocessing and split audit within each fold |
| `sampling_diagnostics.json` | Diagnostics for each fold's sampling arm |
| Susceptibility GeoTIFF files | Full-area raster predictions |

The evaluation pipeline includes **ROC-AUC, PR-AUC, F1 score, Cohen's kappa, precision, and recall**. Specific files depend on the selected experiments and their completion state.

## Reproducibility Notes

To reproduce experiments from the paper, check the following against the manuscript and actual code:

- Input factor rasters, inventory, CRS, and grid alignment.
- Macro-region construction and geographically separated splits.
- Fold-specific preprocessing, DWSS fitting, random seeds, and sample ratios.
- Model variants, hyperparameters, and evaluation definitions.
- Stored experiment configuration and diagnostics.

Do not resume training with a modified XML configuration; start a new output directory instead. The repository's **current default settings may not match every published experiment**.
